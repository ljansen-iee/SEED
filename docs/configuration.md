# Configuration

## Transport — `trans_config.csv`

Located at `transport/trans_config.csv`. The file is auto-generated by
`transport/build_transport_config.py` and can be hand-edited afterwards to
override default CAGR values for specific countries.

The file uses a **wide format**: each row describes one assumption
(type + metric + milestone year + scenario) and each country occupies its own
column. A `default` column holds the fallback value used when no country-specific
override is supplied.

| Column | Type | Description |
| --- | --- | --- |
| `Assumption Type` | string | `CAGR` (growth rate) or `Target` (absolute milestone value) |
| `Metric Name` | string | Metric key (e.g. `Mobility per capita - Passenger`, `Energy Intensity - LDV ICE`) |
| `Year` | int | Milestone year: 2030, 2035, 2040, 2045, or 2050 |
| `Scenario` | string | `BAU`, `Progressive`, or `Optimistic` |
| `default` | float | Value used for any country without an explicit column override |
| `{Country}` | float | Per-country override; one column per country in the model |

**Example** — CAGR for passenger mobility per capita in the BAU scenario for
milestone year 2030, with a Morocco-specific value:

```csv
Assumption Type,Metric Name,Year,Scenario,default,Morocco,Egypt,...
CAGR,Mobility per capita - Passenger,2030,BAU,0.0183,0.0316,0.0183,...
```

## Industry — central long-metric configuration

Run `python -m industry.scripts.generate_industry_config` from the repository
root. Its sole default configuration is
`industry/output_data/CONFIG/INDUSTRY_CONFIG.csv` (the path below **industry**,
not root `output_data/`). The central calculator is
`python -m industry.scripts.calculate_final_energy_demand`.
There is no compatibility API for the former wide industry configuration.

The schema is **long in metrics, years and scenarios**, with country value
columns. It is not the transport `Assumption Type` schema:

| Column | Description |
| --- | --- |
| `metric_1` | Lower-case sector key, e.g. `iron and steel` |
| `metric_2` | `production`, `cagr`, `technology_route`, `fuel_share`, `intensity_base`, `historical_energy_demand`, or `activity_factor` |
| `metric_3` | Production metric, technology route, or growth/intensity metric |
| `metric_4` | Fuel identifier for fuel-share rows; may be blank for other rows |
| `year` | Individual year; CAGR rows instead use intervals such as `2020-2030` |
| `scenario` | `BAU`, `Progressive`, `Optimistic`; historical-energy rows may use `all` |
| `units` | Explicit unit for the row; never inferred from a metric name |
| `{Country}` | Required finite numeric value per selected country; no implicit `default` fallback |

Default countries are Morocco, Egypt, South Africa and Namibia. The base year
is **2020**; default projection years are **2030, 2035, 2040, 2045, 2050**.
Keys are the six dimension columns before `units` and must be unique.

| Quantity | Convention |
| --- | --- |
| Physical production | `t/a`; source aluminium `100t/a` is explicitly converted |
| Base intensity | `MWh/t`; supported `MWh/100t` is explicitly converted |
| Route and fuel shares | `share`, fractions in `[0, 1]`, not percentage values |
| CAGR | `share`, decimal annual rate, strictly greater than -1 |
| Simple-sector base energy | `MWh`, year 2020, scenario `all` |
| Unspecified NMM production placeholders | `activity_factor`, not tonnes or energy |

For example, these are **illustrative individual rows, not a complete runnable
config**; companion route/fuel rows must conserve each hierarchical share group:

```csv
metric_1,metric_2,metric_3,metric_4,year,scenario,units,Morocco
iron and steel,cagr,steel production per year,,2020-2030,BAU,share,0.02
iron and steel,technology_route,dr+eaf,,2030,Optimistic,share,0.4
```

Modify the producing sector assumptions, or use a separately reviewed custom
config through `--config-file`; do not hand-edit generated outputs as a fix.
Generator `--output-path` and `--interim-dir` select an isolated tree.
Calculator `--config-file`, `--interim-dir` and `--output-dir` select that same
tree. Pass `--countries`, `--years` and `--scenarios` explicitly for a subset
run. Missing sources, dimensions, values, intensities and invalid shares fail.
`--config-only` deliberately omits generator derivatives; it does not excuse
missing inputs. Calculator `--no-refresh-interim` rebuilds derivatives in
temporary storage, rather than reading stale cached files.

!!! warning "Emissions readiness is BLOCKED"
    Successful config or demand generation does not approve process emissions.
    Factors lack verified provenance/version/gas/boundary evidence; ammonia SMR
    retains a zero placeholder conflicting with the calculate-here boundary,
    and aluminium's physical CO2-only factor is unverified. Consult the
    [industry methodology](methodology/industry.md#process-emissions-readiness)
    and interim readiness JSON. Do not replace missing physical CO2 with zero.

## Residential — generated end-use configuration

`python residential/build_residential_config.py` writes
`residential/output_data/CONFIG/DEFAULT_RESIDENTIAL_CONFIG.csv`.
Leading columns are `type, metric name, year, scenario, units`, followed by
country columns. The producer currently uses base year 2020, the standard
scenario names, and the ordered SSP pathways `SSP3`, `SSP2`, `SSP1`.
Run the residential scripts by file path because they use sibling imports.
`--output-dir`, `--countries` and `--years` support isolated/subset runs;
the calculator accepts `--config-path` for the generated config.

## Shared shares and CAGRs

The restored root `build_shares.py` and `build_CAGR.py` read
`data/country_specific/UNSD_{Country}-{Year}.csv` and write below root
`output_data/interim/shares/` and `output_data/interim/cagr/`. Both accept
`--input-dir`, `--output-dir`, `--countries` and historical `--years`.
Shares are fractions; share tables include `country, share_mode` and fuel
columns. CAGR tables include `country, sector, suggested_cagr`.
These shared tables feed residential/additional-sector stages; industry owns
its separate central CAGR utilities. Do not substitute one schema for another.

## Root PyPSA exchange

`python build_pypsa_energy_demands.py` replaces the old root exporter. It uses
fresh industry calculations and merges **residential + additional sectors +
transport** into energy totals. Defaults write to root `pypsa_input/`:
`energy_totals_{Scenario}_{year}.csv` and
`industry_totals_{year}_{Scenario}.csv`, each paired with `.units.json`.
The industry `carrier` dimension mixes energy, steel activity and process CO2;
it is not a uniform energy unit. See the authoritative
[PyPSA output contract](data/pypsa-output-contract.md) for schema, units,
readiness gates and unapproved EL/RF scenario mappings.
